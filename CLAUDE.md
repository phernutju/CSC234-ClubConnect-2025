## Event Bill / Payment System (backend/events branch)

Active development area. Data flow:

1. Host creates `EventBill` with `BillItem` list → `event_bill_service.dart`
2. System calculates per-payer split → `BillItem.pricePerPayer`
3. Attendees submit payment slips (image upload to Storage)
4. AI verifies slip → populates `AiVerification` on `Payment` doc
5. `PaymentStatus`: `pending → verifying → verified | rejected`

`EventBillProvider` wraps all bill state. `payment_model.dart` holds `AiVerification` which requires Gemini integration (not yet wired).

## Key design rules

- **Services are widget-free.** No `BuildContext`, no Flutter widgets in `services/`. Return plain Dart types or streams.
- **Providers are the only bridge** between services and UI. Screens call provider methods, never services directly.
- **Models are plain Dart.** No Flutter imports in `models/`. Only `fromFirestore`/`toFirestore` and simple getters.
- **Gemini is called pre-send.** `chat_screen.dart` calls `GeminiService.moderateMessage()` before writing to Firestore. Blocked messages never reach the database.
- **Route args use wrapper classes.** Pass complex objects between routes via `*_args.dart` models, not raw `extra`.

## Working rules (mandatory)

**Assumptions explicit.** If context is missing, state the assumption before acting. Don't hallucinate hidden infrastructure or invent unspecified services.

**Evidence before assertions.** Never claim a change is complete without running verification. "I edited the file" is not done — "I edited the file and here's the `flutter analyze` / `flutter test` output" is done. No "should work now."

**Surface concerns before a major change:**
- Blast radius if this goes wrong?
- What assumptions are we making?
- Reversibility path?
- What are we NOT seeing because of momentum?

**Track scope drift.** Flag when:
- "Just one more thing" accumulates
- Nice-to-haves get treated as must-haves
- The ask was "fix bug X" but we're now "refactoring the entire module"

**Reversibility tiers:**
- **R0 (irreversible)** — STOP. Ask before proceeding. (force-push, dropping data, deleting branches, deploying to prod, deleting Firebase Storage objects, dropping Firestore docs in bulk)
- **R1 (costly to reverse)** — Do it, but say why first. (schema migrations, Firestore rule changes, dependency upgrades, hand-edits to generated files)
- **R2 (easily reversed)** — Just do it. (local file edits, new tests, refactors with green tests)

## Quality gates (must pass before merge)

| Gate | Requirement |
|---|---|
| **Correctness** | `flutter analyze` clean (zero warnings/errors) · `flutter test` green · no regressions in existing widget tests |
| **Security** | No secrets committed · Firestore rules reviewed for any new collection · auth state checked on every protected route |
| **Accessibility** | `Semantics` labels on every interactive widget (buttons, list items, icon-only taps) · WCAG AA contrast · tap targets ≥ 48×48 dp |
| **Performance** | No unbounded `ListView` (use `.builder` + key) · images cached · streams disposed in provider `dispose()` · no heavy work on the UI thread |

## Critical gotchas

- **Firebase setup (one-time):** `firebase login && flutterfire configure` regenerates `lib/firebase_options.dart`. Do not hand-edit that file.
- **`google_generative_ai` not yet in `pubspec.yaml`.** Add it before wiring `GeminiService`.
- **`Firestore whereIn` cap is 30** — chunk large ID lists and merge streams if needed.
- **Routes only via `GoRouter`** — no `Navigator.push`. Auth guard lives in `redirect()` inside `app_router.dart`.
- **`firebase_options.dart` is generated** by `flutterfire configure`. Do not hand-edit.

---

## DO NOT

- **Never** import `flutter/` widgets or Firebase packages inside `models/` — models stay plain Dart.
- **Never** call services directly from screens — go through providers only.
- **Never** write to Firestore or call Gemini from inside a model — that belongs in the service layer.
- **Never** pass raw objects between routes — use `*_args.dart` wrapper classes.
- **Never** let a moderated message reach Firestore — `GeminiService.moderateMessage()` must be called and checked before any Firestore write in `chat_screen.dart`.
- **Never** hand-edit `lib/firebase_options.dart` — regenerate via `flutterfire configure`.
